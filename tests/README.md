# tests —— 检查与用例

| 文件 | 用途 |
|---|---|
| `check.sh` | 结构与一致性检查：skill 校验、上游正文哈希、版本号、品牌色、用例清单。改动 skill 后必跑。 |
| `cases.json` | 测试用例清单：输入、提示词、期望。入库。 |

## 用例材料与产出

- 输入材料放 `tests/cases/<用例 id>/`，产出放 `tests/outputs/<用例 id>/<日期或版本>/`。`cases/` 与 `outputs/` 不入库，因为样本可能含业务数据；本目录下的脚本与清单入库。
- `tc1` 的输入是一份真实业务原型，`reference/` 下是人工迭代后的对照版本。

## 如何评测

1. 新开会话（不继承当前上下文），加载 UEDMaster，按 `cases.json` 的 `prompt` 执行，输入从 `input` 读取。
2. 逐条对照 `expectations` 判定通过 / 不通过，并截图存档。
3. 需要对照时，同一提示词再跑一次不加载 skill 的基线，比较两者。
4. 结果记入 `PROJECT_CONTEXT.md` 的变更日志；单次结果不代表普适效果。

期望项刻意只写底线，不写具体样式，避免把评测变成新的规则约束。
