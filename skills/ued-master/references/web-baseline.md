# 交付底线清单

截图自检时对照检查。这里只列「做对没有」的底线，不规定版式、配色和气质；
下方上游审计清单已经覆盖的（聚焦环、减少动态效果、空状态与错误状态、等宽数字、语义化 HTML 等）不再重复。

要点改写自 [Vercel Web Interface Guidelines](https://vercel.com/design/guidelines)，只取适用于 demo 原型的部分。

## 交互

- **点击区域够大**：移动端可点区域至少 44×44px；桌面端视觉小于 24px 的控件，把可点区域扩到 24px 以上。
- **没有假可点区域**：看起来能点的地方就要能点；复选框、单选框的文字和控件共用一个点击区域。
- **按下有反馈，且更醒目**：悬停、按下、聚焦状态的对比度要高于静止状态，不能比静止状态更淡。
- **加载按钮保留原文字**：提交、生成等按钮进入加载态时，显示加载指示，同时保留按钮原文字，不要整块换成转圈。
- **危险操作可挽回**：删除、作废、批量修改要二次确认，或提供撤销。
- **每个界面都有下一步**：空结果、出错、完成后都给出继续或返回的路径，不留死胡同。

## 移动端

- **输入框字号不小于 16px**：否则 iOS Safari 聚焦时会自动放大页面。
- **不禁止缩放**：不要在 viewport 里设 `user-scalable=no` 或 `maximum-scale=1`。
- **避开刘海与底部横条**：贴边的顶栏、底栏、悬浮按钮使用 `env(safe-area-inset-*)` 留出安全区。

## 内容与状态

- **状态不只靠颜色**：成功、失败、风险等状态同时有文字或图标，色弱用户也能分辨。
- **长短内容都不崩**：用很短、普通、很长三种内容看一遍布局（长项目名、长人名、空字段），不出现撑破、重叠或逐字折行。
- **骨架屏和最终内容同形**：加载骨架的尺寸与布局和真实内容一致，加载完不跳动。

## 深色主题

- **声明 `color-scheme: dark`**：深色页面在 `<html>` 上设置，让滚动条、原生下拉框等系统控件也跟着变深。
- **原生 `<select>` 显式设背景色和文字色**：避免 Windows 深色模式下出现白底白字。

## 对比度口径

对比度统一按 WCAG 2.x 计算：正文 ≥4.5:1，图标、边框等界面元素 ≥3:1。不使用原文推荐的 APCA，避免和品牌色规则出现两套口径。
